## 3. 阶段二：建立统一的台球桌几何与坐标规范

### 3.1 尺寸原则

以标准美式球桌的**实际击球区域**为尺寸基准，击球区域长宽比为 2:1。必须区分：

1. 击球区域（台呢有效区域）。
2. 库边内侧的实际边界。
3. 袋口开口与袋角/袋口结构。
4. 外框及桌架的整体尺寸。

不能把外框尺寸当作击球区域尺寸，也不能将 2:1 比例直接套到整张桌子的外轮廓。

优先沿用目标项目已经存在且被物理系统使用的尺寸参数。如果这些参数明显错误或互相矛盾，先确定一个权威尺寸配置，再有计划地迁移引用。不得在多个文件里各自硬编码一套尺寸。

### 3.2 单一数据源

建立或整理统一的台球桌尺寸配置（具体文件和类型根据现有架构决定），至少覆盖：

- 有效击球区域长度、宽度。
- 球半径/直径。
- 台面高度。
- 库边高度、宽度及碰撞面位置。
- 外框宽度、厚度及高度。
- 六个袋口的中心位置、开口尺寸和类型。
- 袋口排除区/捕获区所需参数。

视觉模型和物理系统必须引用同一套权威参数，或通过明确、可测试的转换函数从同一数据源派生。禁止视觉和物理分别维护两份容易漂移的桌面尺寸。

若原项目已有等价配置，不要为形式统一而重复造轮子。

### 3.3 坐标系

遵循目标项目现有约定：物理台面使用 X/Z 平面、Y 为高度；Three.js 使用 Y-up。确认桌长、桌宽方向及六袋索引映射，并在代码中清楚记录。

必须明确：

- 桌面中心原点还是角点原点。
- 长轴和短轴方向。
- 六个袋口的稳定顺序/索引。
- 物理坐标到 Three.js 世界坐标的映射。
- 模型是否存在父级旋转/缩放。

不要通过散落在渲染代码中的正负号修正坐标错误。使用单一、可测试的转换规则。

## 4. 阶段三：重建正确的 3D 台球桌结构

以标准美式六袋球桌为目标，参考项目仅提供外观层次和配色方向。

### 4.1 台呢与有效击球区域

- 形成完整、平整、连续的绿色击球表面。
- 表面边界必须与六个袋口和库边开口正确衔接。
- 台呢不可被错误的外框几何体覆盖，也不能出现可见缝隙。
- 材质呈现细腻、克制的台呢质感，避免明显噪点和夸张纹理。
- 标线（如项目需要）必须按桌面坐标定义，不能用装饰线掩盖几何错误。

### 4.2 库边与橡胶库

- 按六袋结构合理拆分库边段，而不是用完整封闭矩形围住桌面。
- 库边内侧击球面位置必须与物理碰撞面一致。
- 库边高度与球体半径相匹配，视觉上球体应自然贴近库边。
- 角袋和中袋附近应正确留出袋口，端部几何衔接自然。
- 不允许库边穿过袋口、封住袋口或出现明显悬空/穿模。
- 视觉库边和物理碰撞边界必须可通过参数或测试相互核对。

### 4.3 六个球袋

必须具备标准布局：

- 左上角袋、右上角袋。
- 左侧中袋、右侧中袋。
- 左下角袋、右下角袋。

要求：

- 角袋和中袋采用符合实际结构的开口形态，不要把六个袋都做成相同圆孔。
- 袋口边缘与库边断口自然衔接。
- 袋口内部有合理的深色/袋腔视觉层次。
- 袋口尺寸与球体直径相适配。
- 袋口可见开口不能被台呢、库边或桌框遮挡。
- 物理捕获区必须与视觉开口对齐，六个袋的索引与物理事件映射一致。
- 不得只在桌面上放六个黑色圆形贴片来伪装球袋。

如果当前物理系统使用简化的二维捕获模型，保留其合理部分；本次重点是让可见袋口与该模型一致，不要求无必要地开发完整袋腔动力学。

### 4.4 木质外框与桌架

- 桌框环绕库边与台呢，厚度、宽度、高度具有合理层次。
- 参考项目的深色木质框架和绿色台呢配色，但提升到目标项目的 3D 材质表现。
- 桌框与库边之间不能互相穿插或遮挡袋口。
- 桌架/腿部若原项目已有，先修复其与桌面的连接；若本次没有必要，不要额外扩大范围。
- 高光、反射和阴影保持克制，优先保证桌面可读性。

### 4.5 几何实现策略

根据现有代码选择合适的 Three.js 几何方案，例如 BufferGeometry、BoxGeometry、ShapeGeometry、ExtrudeGeometry 或自定义 BufferGeometry。不要为了使用某个 API 而强行采用复杂方案。

几何体应按职责组织、命名清晰，便于单独调整和测试。可复用材质和几何资源，正确管理 dispose 生命周期，避免重建场景时泄漏。

## 5. 阶段四：保证视觉模型与物理模型一致

这是本任务的 P0/P1 核心验收项。

### 5.1 必须核对的项目

- 有效击球区域边界。
- 六段库边的物理碰撞面。
- 球体半径与球心高度。
- 球袋开口中心和方向。
- 球袋捕获区域/捕获半径。
- 球袋索引顺序和进袋事件。
- 物理坐标与渲染坐标转换。
- 球体在桌面上的视觉接触位置。

### 5.2 具体行为要求

- 球体在正常击球状态下不会穿过完整库边。
- 球体不会在库边上方悬浮或陷入台呢。
- 球体碰撞反弹的位置与视觉库边一致。
- 六个袋均能正常捕获球体。
- 球体进入袋口时，不应被可见几何体挡住。
- 不应出现视觉上已进袋、物理上却继续在桌面运动的明显错位。
- 不应出现物理上已判定进袋、视觉上却还停留在桌面中央的明显错位。

### 5.3 修复原则

- 先查明坐标和尺寸来源，再修正。
- 不得仅在渲染模型上整体缩放来适配错误物理边界。
- 不得随意扩大袋口捕获半径来掩盖袋口模型错误。
- 不得关闭碰撞或删除边界来让球“更容易进袋”。
- 如确需调整物理参数，必须说明其依据，并增加回归测试。
- 物理模块继续保持不依赖 Three.js 的架构边界。
